# Dev Spec — US-GRP-009: registro explícito de un agente

Plano compacto (AADD ligero) de [US-GRP-009](../user-stories/US-GRP-009-registro-explicito-agente.md). Parte del modelo de sesión de [US-GRP-007](./US-GRP-007-dev-spec.md) (estados, origen, presencia, `sessions.list`, `session.state`) y del almacén de TS-GRP-001, que ya tiene las tablas `sessions` y `attribution_records` (append-only). Sigue ADR-GRP-005 § 6.6 (M7), ADR-GRP-012 regla 3 y ADR-GRP-013 § 2 y § 3.

**Qué entrega**: el método `registration.register` (no reservado) y `registration.withdraw` (reservado) en el canal, y los comandos `raptor agent register <agente> [--worktree <ruta>]` y `raptor agent withdraw <agente> [--worktree <ruta>]`. Registrar crea una sesión con origen "registrado" (o confirma la detectada del mismo agente), sigue "Activo"/"Inactivo" con el umbral de US-GRP-007, figura presente hasta que se retira y sobrevive al reinicio del motor. Un "otro agente" registrado como única sesión de su worktree recibe los eventos de Git de ese worktree. Es el eslabón de M1 hacia US-GRP-004 y la captura continua (US-TMC-004).

Todas son **Decisión del orquestador (2026-10-05), validada por el Arquitecto y el PO**. Los dos dieron "aprobada con ajustes"; la columna de la derecha recoge los ajustes ya incorporados (A = Arquitecto, PO = Product Owner).

## 4. Riesgos y pendientes

- **Claude Code registrado sin detección** (instalado con npm, D4 de US-GRP-007): la sesión existe y muestra su estado, pero sus eventos solo se atribuyen con S3, que necesita el proceso. Hasta que el registro guarde la identidad del proceso que se registra (ADR-TMC-005, con US-MCP-006), quedan "sin atribuir", nunca mal atribuidos.
- **Suplantación**: un proceso que no es Claude Code puede registrarse como "otro agente" con cualquier nombre no reservado en su propio worktree, como prevé ADR-GRP-005 § 6.6; el origen "registrado" visible es la medida (BR-CONS-003). Un Claude Code sin detectar (instalado con npm) no puede registrarse a sí mismo como Claude Code (`agent-mismatch`): lo registra el desarrollador.
- **Worktree compartido** (PO): con Claude Code detectado y Codex registrado en el mismo worktree, los commits de Codex quedan "sin atribuir" (nunca mal atribuidos). Es una limitación visible para US-GRP-011 y la Time Machine.
- **Un agente lanzado por otro**: un Codex que desciende de un Claude Code detectado se resuelve como Claude Code y no puede registrarse como Codex (`agent-mismatch`); lo registra el desarrollador.
- **Retiro por el propio agente** (`unregister_agent`): US-MCP-006. Hoy un agente que lo pide recibe el rechazo de comando reservado, auditado.
- **Linux y Windows**: los escenarios de punta a punta corren en macOS; Linux con las pruebas de `crates/core` del CI; Windows sin transporte. Pendiente: etapa de validación multiplataforma.
